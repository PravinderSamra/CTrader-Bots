Section 01
Project Overview & Goals

This dashboard is a daily gold trading intelligence tool for a day trader who uses ICT / Smart Money Concepts (SMC) methodology, trading XAUUSD on the 1M / 5M / 1H timeframe hierarchy with entries only in the direction of the established trend (HH/HL or LH/LL structure).

What the dashboard does: Aggregates all the macro and market data that a professional gold analyst would review each morning, presents it in a clean tile layout, and then uses a Claude AI agent to read all those data points and write a plain-English daily intelligence briefing — telling the trader what is likely to happen in gold today and why, in terms a beginner can understand.

Primary goals

  • One screen, every morning. No visiting 8 different websites. Open the dashboard at 07:00 GMT, everything is already populated.
  • Real-time prices from CTrader MCP. Gold, silver, indices and forex pairs pulled via the local CTrader MCP HTTP server — zero delay, zero cost.
  • Zero monthly API fees. All non-price data sourced from free APIs (FRED, Finnhub) or web scraping.
  • Refresh on demand. A single "Refresh" button re-fetches all data and optionally re-generates the AI briefing mid-session.
  • AI Intelligence Briefing. A structured paragraph written by Claude (via Anthropic API) that synthesises all data points into a plain-English trade context and directional bias for the day — not a one-liner, a full professional briefing.
  • Callable agent skill. The briefing generation function is structured so Claude Code can call it as a standalone agent skill from the command line or schedule it independently.

CTrader MCP connection: The dashboard assumes the CTrader MCP HTTP server is running locally on the trader's machine (same machine as the browser). The base URL should be configurable via a .env file: VITE_CTRADER_MCP_URL=http://localhost:PORT. Claude Code should check the existing CTrader-Bots repo for the MCP server port used in other agent skills and match it exactly. If the MCP is unreachable, tiles degrade gracefully with a "CTrader offline" badge and retain the last cached price.
GitHub Action as scheduler: Because GitHub Pages is static, there is no server to run cron jobs. Instead, a GitHub Action (see Section 09) runs at 06:45 GMT every weekday, calls FRED + scrapers, writes public/data/daily-snapshot.json to the repo, and triggers a redeploy. The React app then reads this file on load. Real-time prices always come from CTrader MCP directly.

FRED API Setup

Register for a free API key at fred.stlouisfed.org/docs/api/api_key.html. Store key as GitHub Actions secret FRED_API_KEY. Base URL: https://api.stlouisfed.org/fred/series/observations?series_id=DGS10&api_key=KEY&file_type=json&sort_order=desc&limit=1

Finnhub API Setup

Register for a free key at finnhub.io. Free tier allows 60 calls/minute — more than sufficient. Store as GitHub secret FINNHUB_API_KEY and expose to Vite as VITE_FINNHUB_KEY for client-side calendar/news calls. Economic calendar endpoint: https://finnhub.io/api/v1/calendar/economic?from=YYYY-MM-DD&to=YYYY-MM-DD&token=KEY

Anthropic API Setup

Key stored as GitHub secret ANTHROPIC_API_KEY and exposed via VITE_ANTHROPIC_KEY for client-side briefing generation. Model: claude-sonnet-4-6. Max tokens: 1200 for the briefing.

CFTC COT Data

CFTC publishes weekly Commitments of Traders data every Friday. Download URL for COMEX gold futures (legacy format): https://www.cftc.gov/dea/futures/deacmesf.htm. Parse the CSV to extract the "Gold" row — specifically: Non-Commercial Long, Non-Commercial Short, and the net position (Long − Short). Store net positioning value and the week-over-week change.

Scraping resilience: All scrapers in the GitHub Action should implement try/catch and write null values to the JSON on failure rather than crashing the action. The dashboard should handle null values gracefully with a "Data unavailable" state per tile rather than breaking the whole page.

Individual Tile Specifications

TILE 1 · Yields & Rates

Data: 10Y yield, 2Y yield, 10Y real yield, 2s10s spread, 10Y breakeven, 5Y breakeven, 5y5y forward inflation

Source: FRED API (via daily-snapshot.json)

Display: Each row shows label, value, and a directional arrow (▲▼→) vs prior day. Positive real yield number = red tint. Inverted curve (negative 2s10s) = amber badge.

What it means (for AI context): Higher real yields → bearish gold. Rising breakevens with stable nominals → bullish gold. Inverted curve → macro stress building.

TILE 2 · Dollar & FX

Data: DXY, EUR/USD, USD/JPY, USD/CHF, USD/CNH

Source: CTrader MCP (real-time)

Display: DXY as the headline number. Each pair shows value and % change on the day. DXY up = amber. DXY down = green. USD/CNH shown as "China proxy".

What it means: DXY rising = bearish gold (gold priced in dollars, stronger dollar = gold more expensive globally). USD/CNH rising = Chinese buyers paying more = demand floor signal.

TILE 3 · Economic Calendar

Data: Today's events with time (GMT), impact level (●●● high, ●● medium), event name, previous, forecast, actual (once released)

Source: Finnhub API (real-time on load)

Display: Chronological list, high-impact events highlighted in gold border. Count of high-impact events at top. Time shown in GMT. "RELEASED" badge once actual populates. Events filtered to: US, EUR, GBP, JPY.

Key events to flag prominently: CPI, PCE, NFP, FOMC, ISM, GDP, PPI, Initial Claims, JOLTS.

TILE 4 · Gold Panel

Data: XAUUSD live price, XAGUSD live price, Gold/Silver ratio, GVZ (gold VIX), Average Daily Range, ADR used today

Source: CTrader MCP (prices); daily-snapshot.json (GVZ)

Display: XAUUSD is the hero number (large). Silver and ratio below. GVZ shown with context (below 15 = calm, 15–25 = normal, above 25 = elevated). ADR bar showing % of typical range consumed.

ADR Calculation: 14-day average of (daily high − daily low) from CTrader OHLC history. "Used today" = (today's high − today's low) as % of ADR.

TILE 5 · Risk Tone

Data: US500, GER40, UK100 (% change on day), VIX level and direction

Source: CTrader MCP (indices); Finnhub (VIX)

Display: Each index shows % change with colour (green up / red down). VIX shown with context band. A computed "Risk Tone" badge at the bottom: RISK-ON (green), RISK-OFF (red), NEUTRAL (grey). Logic: VIX >20 + all indices negative = Risk-Off; all indices positive + VIX <16 = Risk-On; else Neutral.

What it means: Risk-Off can mean gold bid (safe haven) — but also watch for forced selling (see briefing context). Risk-On typically bearish for gold unless in debasement regime.

TILE 6 · Fed Expectations

Data: Implied probability of Cut / Hold / Hike at the next FOMC meeting

Source: CME FedWatch (web scrape via GitHub Action)

Display: Horizontal bar chart for each outcome (%) with colour coding: Cut = green, Hold = grey, Hike = red. Meeting date shown. A "Market Pricing" summary line: "Market pricing 62% chance of HOLD in Sep."

What it means: Rising cut probability = dovish = bullish gold. Rising hike probability = hawkish = bearish gold. A sudden shift in these probabilities intraday (triggered by data) is a key momentum driver.

TILE 7 · Positioning (COT)

Data: Net speculative positions in COMEX gold futures (Non-Commercial Long − Short), week-over-week change, crowding assessment

Source: CFTC.gov (weekly Friday release, GitHub Action)

Display: Net position number with direction arrow. WoW change highlighted. Crowding label: "CROWDED LONG" (caution, squeeze risk), "NEUTRAL", "CROWDED SHORT" (potential squeeze higher). Crowded threshold: top/bottom 20% of 52-week range.

Note: Updates only on Fridays — display the date of the most recent report clearly so the trader knows its age.

TILE 8 · ETF Flows (GLD)

Data: GLD ETF holdings in tonnes, week-over-week change, trend direction (3-week rolling)

Source: SPDR GLD website scrape (spdrgoldshares.com)

Display: Holdings in tonnes as headline. WoW change with arrow. Trend badge: "INFLOW (3W)" or "OUTFLOW (3W)". Contextual note: "Institutional investors adding / reducing gold exposure."

Session Awareness: The header should show which trading session is currently live (Asian / London / New York / Overlap) based on current GMT time, and countdown to the next session open. Key times to hard-code: Asian open 00:00 GMT, London open 08:00 GMT, NY open 13:30 GMT, London close 16:30 GMT, NY close 21:00 GMT. London–NY overlap (13:00–16:00 GMT) should be flagged as "PRIME SESSION."
Section 07
AI Intelligence Briefing — System Prompt & Format

How it works

When the user clicks "Generate Briefing", the dataAggregator.ts service assembles all available data from every tile into a structured JSON object. This is passed to the Anthropic API with the system prompt below. The response is rendered in the briefing panel.

System Prompt for Claude

You are a senior gold trading analyst and market intelligence advisor.
Your job is to write a daily intelligence briefing for a beginner day 
trader who uses ICT / Smart Money Concepts methodology to trade XAUUSD.

The trader only trades WITH the trend (buying into uptrends, selling 
into downtrends) using the 1H chart to determine trend direction, 
the 5M chart for signals, and the 1M chart for precise entry. 
They trade during the London and New York sessions.

You will receive a structured JSON snapshot of all the day's market data.

Write a SINGLE flowing briefing paragraph (200–300 words) using PLAIN, 
BEGINNER-FRIENDLY language. Avoid jargon wherever possible. 
When you use a financial term, briefly explain what it means in brackets.

Your briefing MUST follow this structure within the single paragraph:
1. REGIME LINE: Which forces are most relevant today and why 
   (e.g. "today is primarily driven by interest rate expectations").
2. OVERNIGHT CONTEXT: What happened in Asia, where gold opened London,
   direction of the dollar and yields overnight, any key headlines.
3. DIRECTIONAL BIAS with plain reasoning: Is the day likely to favour 
   gold going UP, DOWN, or being CHOPPY — and in simple terms, WHY.
4. CONFIDENCE SCORE: Express confidence in the bias as X/10. Explain 
   what would change the view.
5. EVENT RISK: Any scheduled news today, when it hits (GMT), what to 
   expect and how to position around it.
6. KEY LEVELS: The most important price levels to watch today. Use 
   the ADR data to comment on how much move is likely remaining.
7. TRADE INTEGRATION: Explicit guidance on whether today is a good 
   day for trend-following trades, what size/conviction is appropriate.

End with one sentence that a beginner can screenshot and remember for 
the day — a plain English summary of the single most important thing 
to know.

CRITICAL RULES:
- Use plain English throughout. Write as if explaining to a smart 
  person who is new to financial markets.
- Never say "in conclusion" or "to summarise".
- Do NOT make up data. Only use what is in the JSON you receive.
  If data is null or unavailable, say so and explain what you'd 
  normally look for.
- The bias gauge score should also be returned as a structured field
  outside the paragraph so the UI can render the visual gauge.
  Return your response as JSON: 
  { "biasScore": -5 to +5 (negative = bearish, positive = bullish), 
    "biasLabel": "BEARISH" | "NEUTRAL" | "BULLISH",
    "confidence": 1-10,
    "briefing": "your paragraph here" }

Bias Gauge Visual

The biasScore from Claude's JSON response (−5 to +5) drives a visual horizontal gauge in the briefing panel. It should be rendered as a bar with a sliding indicator — not a number, a visual. Bearish end is red (#E85050), bullish end is green (#3BB57A), the midpoint is grey. The indicator dot is gold-coloured. This is the signature design element of the dashboard.

Both fonts are available via Google Fonts — include in index.html <head>. All numeric data fields MUST use JetBrains Mono. This is non-negotiable — it distinguishes data from copy and gives the terminal feel.

Layout Rules

  • No rounded corners on tiles. Use border-radius: 3px maximum. Sharp corners feel more professional / terminal-like.
  • Borders not shadows. Use border: 1px solid #2A2B35 for tile edges. No box-shadow on tiles.
  • Tight but breathable grid. Main tile grid uses gap: 12px. Padding inside tiles: 16px 18px.
  • Full-width header bar with a thin gold bottom border (border-bottom: 1px solid #C9952A).
  • Tile eyebrow labels in JetBrains Mono, 9–10px, letter-spacing 0.15em, uppercase, gold colour. This is how each tile identifies itself.
  • Data values: large and mono. The headline number in each tile should be 22–28px JetBrains Mono. Secondary values 13–14px. Muted labels 11px.
  • Direction arrows. Use Unicode ▲ ▼ → characters (not icon libraries). Colour them green/red/grey respectively.
  • No emojis anywhere on the dashboard. Use Unicode symbols only.
  • The briefing panel spans full width at the bottom with a 2px gold top border to visually separate it as the "intelligence layer."

Animation — restrained by design

  • Price updates: a 0.3s colour flash (green or red) on the number when it changes. Then returns to default. No jank.
  • Briefing generation: a typing-cursor animation while Claude streams. Show a subtle pulsing gold dot while waiting.
  • No other animations. No page-load transitions, no hover scale effects, no CSS keyframe loops. This is a data tool, not a marketing page.

Responsive behaviour

Desktop-first (the trader uses this on a screen, not mobile). Minimum width: 1200px. Below 1200px, tiles stack to a 2-column layout. Do not engineer for mobile — it's a distraction from the desktop experience.

What NOT to do — explicit prohibitions

  • No Tailwind. Use custom CSS with the token variables defined above. Tailwind produces generic, recognisable output.
  • No gradient backgrounds on tiles. Flat colour only.
  • No icon libraries (Lucide, FontAwesome, etc.). Unicode symbols only.
  • No card hover lift effects. Tiles are static.
  • No blue colour for anything except the steel-blue accent (#5B8CDB), which is used sparingly for USD/bond context only.
  • No white backgrounds anywhere. The entire dashboard is dark.
Section 09
GitHub Actions — Scheduled Data Fetcher

The file .github/workflows/daily-data-fetch.yml runs a Node.js script every weekday at 06:45 GMT to fetch all non-real-time data and write it to public/data/daily-snapshot.json.

# .github/workflows/daily-data-fetch.yml
name: XAUUSD Daily Data Fetch

on:
  schedule:
    - cron: '45 6 * * 1-5'   # 06:45 GMT, Mon–Fri
  workflow_dispatch:       # Also triggerable manually

jobs:
  fetch-data:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with: { node-version: '20' }

      - name: Install deps
        run: cd xauusd-dashboard && npm ci

      - name: Fetch data
        run: npx ts-node scripts/fetch-static-data.ts
        env:
          FRED_API_KEY: ${{ secrets.FRED_API_KEY }}

      - name: Commit snapshot
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git add xauusd-dashboard/public/data/daily-snapshot.json
          git diff --staged --quiet || git commit -m "chore: daily data snapshot $(date -u +%Y-%m-%d)"
          git push

The fetch-static-data.ts script should:

  1. Fetch all 7 FRED series (DGS10, DGS2, DFII10, DFII5, T10YIE, T5YIE, T5YIFR) — one API call per series. Calculate 2s10s spread from the values.
  2. Scrape CME FedWatch page for the next FOMC meeting probability table using a HEAD request and HTML parsing (cheerio library).
  3. Scrape CBOE for GVZ — fetch the CBOE gold volatility page and extract the index level.
  4. Scrape SPDR GLD page for holdings in tonnes (spdrgoldshares.com/usa/gold/en).
  5. Fetch CFTC COT data — download the legacy futures CSV from CFTC.gov, parse the gold row for net speculative positioning. Only update if it's a Friday or the data is stale (>7 days old).
  6. Wrap each operation in try/catch — on failure, write the previous value if available, or null. Never crash the entire script.
  7. Write output to xauusd-dashboard/public/data/daily-snapshot.json with a top-level generatedAt ISO timestamp.
Section 10
GitHub Pages Deployment

Build and deploy the React app to GitHub Pages from the xauusd-dashboard/ subfolder. Match the pattern already established in the CTrader-Bots repo for other dashboard projects.

  • Vite base path: Set base in vite.config.ts to match the GitHub Pages URL path (e.g. /CTrader-Bots/xauusd-dashboard/)
  • Deploy workflow: Add a second GitHub Action at .github/workflows/deploy-dashboard.yml that triggers on push to main and runs npm run build, then deploys the dist/ folder to the gh-pages branch using actions/deploy-pages@v4
  • Environment variables for Vite: VITE_ prefixed vars (VITE_FINNHUB_KEY, VITE_ANTHROPIC_KEY, VITE_CTRADER_MCP_URL) must be set as GitHub Actions secrets and passed during the build step
  • CTrader MCP URL default: http://localhost:8080 — check existing CTrader agent skill code in the repo for the actual port
Note on VITE_ANTHROPIC_KEY in a public GitHub Pages site: The API key will be embedded in the built JavaScript bundle and visible to anyone who views the source. This is acceptable for a personal tool on a personal repo — the key is rate-limited to the owner's account. However, Claude Code should add a clear comment in the code noting this and suggesting the user regenerate the key if the repo ever goes public. Do not implement a backend proxy — keep it simple.
Section 11
Agent Skill Specification

The intelligence briefing generation function must be extractable as a standalone agent skill that Claude Code can call independently — for example, from the command line, on a schedule, or as part of a larger agentic workflow.

SKILL: xauusd-daily-brief

File: scripts/agent-skill-daily-brief.ts

What it does: Fetches all macro and market data independently (does not rely on the dashboard UI being open), assembles the data object, calls the Anthropic API, and outputs the structured briefing JSON to stdout — or optionally writes it to a dated file in briefings/YYYY-MM-DD.json.

Input: No arguments required. Reads environment variables for API keys. Optionally accepts --save flag to write to file.

Output (stdout): The same JSON structure Claude returns — biasScore, biasLabel, confidence, briefing paragraph.

Dependencies: Same as the fetch-static-data script. Can share utility functions.

Designed for: Future extension — e.g. emailing the briefing, posting to a webhook, integrating into a pre-trading-session automation.

Section 12
Build Instructions for Claude Code
READ FIRST — mandatory pre-build steps:
1. Read /mnt/skills/public/frontend-design/SKILL.md before writing any CSS or component code.
2. Check the existing CTrader-Bots repo for: (a) the CTrader MCP HTTP port used in other agent skills, and (b) the GitHub Pages deploy workflow pattern already established — replicate it exactly.
3. Do not install Tailwind, shadcn, MUI, Ant Design, or any UI component library. Raw CSS + React only.
4. Do not use any paid APIs. Every data source in this spec is free or scraped.

Recommended build sequence

  1. Create folder structure. Create xauusd-dashboard/ and all subdirectories. Copy this spec file into research/.
  2. Initialise Vite + React + TypeScript project inside the folder. Install only: react, react-dom, typescript, vite, cheerio (for scraping in scripts), tsx or ts-node (for scripts).
  3. Build the design token CSS file (styles/tokens.css) with all variables from Section 08. This is the foundation of the entire UI.
  4. Build the data hooks in order: useCTraderPrices first (proves MCP connectivity), then useFredData (reads from snapshot.json), then useEconomicCalendar (Finnhub), then the remaining hooks.
  5. Build each tile component one at a time. Test with mock data first, then wire to real hooks.
  6. Build the Header component with live gold price, session clock, and refresh controls.
  7. Build the AI briefing panel and bias gauge. Test with a hardcoded mock briefing first, then wire to anthropicBriefing.ts.
  8. Build the GitHub Actions workflow (daily-data-fetch.yml) and the fetch-static-data.ts script. Test locally with npx ts-node scripts/fetch-static-data.ts.
  9. Configure GitHub Pages deployment following the existing repo pattern.
  10. Build the standalone agent skill (agent-skill-daily-brief.ts) and test it runs independently.
  11. Final QA: Verify all null/error states are handled gracefully. Verify design matches the spec — check fonts are loading, all numbers use JetBrains Mono, colours match the palette, no border-radius > 3px on tiles.

GitHub Secrets to configure

  • FRED_API_KEY — Free from fred.stlouisfed.org/docs/api/api_key.html
  • FINNHUB_API_KEY — Free from finnhub.io (also set as VITE_FINNHUB_KEY)
  • ANTHROPIC_API_KEY — Owner already has this (also set as VITE_ANTHROPIC_KEY)
  • VITE_CTRADER_MCP_URL — The local HTTP MCP server URL (check existing repo code)
Definition of done: The dashboard is accessible at the GitHub Pages URL. On load, all tiles populate with real data (CTrader MCP prices live, snapshot data from the GitHub Action). Clicking "Generate Briefing" calls the Anthropic API and renders a structured paragraph with the bias gauge. The standalone agent skill runs from the command line and outputs valid JSON. All scraping and FRED data updates automatically at 06:45 GMT each weekday via the GitHub Action.
